# СОСТАВЛЕНИЕ ТЗ ДЛЯ ПРЕДМЕТНОЙ ОБЛАСТИ

## Разработка программного продукта «BidOnline» для автоматизации процесса проведения онлайн-аукционов

### 1. Введение

**1.1. Полное наименование программного продукта**

Автоматизированная система «BidOnline» для автоматизации процесса проведения торгов в сети Интернет на платформе для онлайн аукционов.

**1.2. Краткая характеристика области применения**

Система предназначена для использования на интернет-платформах, организующих проведение аукционных торгов между продавцами и покупателями. Автоматизации подлежит процесс проведения аукциона в режиме реального времени: от публикации лота продавцом до завершения торгов, фиксации победителя и формирования финансовых документов.

**1.3. Основание для разработки**

Разработка выполняется на основании индивидуального проекта по МДК.02.01 «Технология разработки программного обеспечения» и МДК.02.02 «Инструментальные средства разработки программного обеспечения» в ГБПОУ КК «Ейский полипрофильный колледж».

### 2. Назначение разработки

**2.1. Функциональное назначение**

Система предназначена для автоматизации процесса «Проведение онлайн-аукционов», включая следующие подпроцессы:
- публикация и управление лотами;
- приём и обработка ставок в реальном времени;
- автоматическое отслеживание времени завершения торгов с антиснайперским механизмом;
- фиксация победителя и завершение аукциона;
- формирование финансовых обязательств;
- информирование участников о ходе торгов и результатах;
- ведение истории всех торговых операций и ставок.

**2.2. Эксплуатационное назначение**

Система предназначена для использования следующими категориями пользователей:
- **Продавцы** — создание и управление лотами, просмотр хода торгов, получение финансовой отчётности;
- **Покупатели** — просмотр каталога лотов, участие в торгах, оплата выигранных товаров;
- **Администраторы** — модерация лотов, мониторинг активности пользователей, управление системными настройками;
- **Технические специалисты** — установка и настройка системы, резервное копирование, мониторинг.

### 3. Требования к программному продукту

**3.1. Требования к функциональным характеристикам**

3.1.1. **Регистрация и управление пользователями**
- Регистрация с подтверждением электронной почты
- Верификация документов для продавцов
- Авторизация по логину и паролю
- Разделение по ролям (продавец, покупатель, администратор, техспециалист)
- Личный кабинет с возможностью редактирования данных

3.1.2. **Публикация и управление лотами**
- Создание карточки лота (название, описание, категория, начальная цена, шаг ставки, срок торгов)
- Загрузка изображений (не менее 3 шт.)
- Автоматическая проверка корректности заполнения
- Возможность редактирования или снятия лота до начала торгов

3.1.3. **Приём и обработка ставок**
- Приём ставок в режиме реального времени
- Проверка превышения текущей цены на установленный шаг
- Мгновенное обновление текущей цены для всех участников
- Время отклика не более 1 секунды
- Поддержка одновременного участия не менее 1000 пользователей

3.1.4. **Отслеживание времени завершения торгов**
- Автоматический отсчёт времени до завершения торгов
- Антиснайперский механизм (продление на 5 минут при ставке в последние 5 минут)
- Отображение времени в формате «дни:часы:минуты:секунды»
- Автоматическое завершение аукциона по истечении времени

3.1.5. **Фиксация победителя и завершение аукциона**
- Автоматическое определение победителя (последняя и наибольшая ставка)
- Фиксация финальной цены продажи
- Перевод лота в статус «завершён»
- Генерация уведомлений для продавца и покупателя
- Перевод лота в статус «не состоялся» при отсутствии ставок

3.1.6. **Формирование финансовых обязательств**
- Автоматическое формирование счёта на оплату для покупателя
- Расчёт и удержание комиссионного сбора с продавца (например, 5%)
- Интеграция с внешними платёжными системами
- Формирование финансовой отчётности

3.1.7. **Информирование участников**
- Уведомления о: подтверждении регистрации, превышении ставки, завершении торгов, победе, необходимости оплаты
- Отправка через интерфейс системы и по электронной почте
- Настройка способа получения уведомлений

**3.2. Требования к надёжности**
- Сохранение работоспособности при 1000 активных пользователей
- Время восстановления после сбоя — не более 30 минут
- Ежедневное автоматическое резервное копирование БД
- Исключение потери данных при некорректном завершении работы
- Система мониторинга с оповещением администраторов

**3.3. Требования к информационной совместимости**
- СУБД: PostgreSQL (рекомендовано) или MySQL
- Выгрузка данных в форматы Excel, PDF, CSV
- Импорт данных из CSV или Excel

**3.4. Требования к программной совместимости**
- Серверная часть: Linux Ubuntu Server / Windows Server
- Клиентская часть: любой современный браузер (Chrome, Firefox, Safari, Edge)
- Адаптивный дизайн для компьютеров, планшетов, смартфонов
- Клиентское оборудование: Intel Core i3, 4 ГБ ОЗУ, интернет

**3.5. Требования к техническим средствам**

| Наименование | Требования |

**3.6. Требования к информационной безопасности**
- Авторизация по логину и паролю
- Хранение паролей в зашифрованном виде (хэширование)
- Двухфакторная аутентификация для продавцов и администраторов
- Разграничение доступа по ролям
- Передача данных по HTTPS с SSL-сертификатами
- Защита от SQL-инъекций, XSS и других уязвимостей
- Логирование критических действий

### 4. Требования к программной документации
